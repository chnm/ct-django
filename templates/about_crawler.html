Threadbare: The Museum API Crawler

Jason A. Heppler, Ph.D.
Roy Rosenzweig Center for History and New Media, George Mason University

The Connecting Threads project uses a custom web crawler we call Threadbare that's built into our web app platform, Django, to automatically retrieve and process textile-related records from museum APIs around the world.

How It Works

Threadbare connects to museum APIs (an Application Programming Interface) using authenticated requests and searches for textile-related objects using specific keywords and parameters. The crawler is designed to respect API rate limits and handle large datasets efficiently. We retrieve museum data as structured JSON responses, which are then parsed and processed to extract relevant metadata and media files.

The crawler operates in this way:

  1. Authenticates and queries the API: When a fetch is triggered by a team member, Threadbare uses museum-provided API keys to search collections for textile-related objects based on keywords, material types, date ranges, or project-specific exhibits and keywords.
  2. Retrieves comprehensive metadata: Collects object titles, dates, descriptions, material specifications, provenance information, and catalog references.
  3. Downloads associated media: Fetches high-resolution images, thumbnails, and IIIF manifest URLs when available, storing them for preservation and access not dependent upon the original source.
  4. Stages data for review: All retrieved records are placed in a staging area where they remain unpublished until reviewed by project researchers.
  5. Enables curatorial workflow: Researchers can preview staged items, edit or enhance metadata, link related records, and approve items for publication to the public database.
  6. Maintains provenance: Each published record retains a link to its original museum source, including the original museum ID and source URL for attribution and verification.

The crawler runs on-demand rather than continuously, allowing the team to target specific collections. This approach ensures quality control and prevents the database from being overwhelmed with potentially irrelevant records.

Technical Details

Architecture: Threadbare is built with Python 3.11+ and Django 5.0, leveraging Django's ORM for data persistence and model validation. The crawler uses asynchronous requests via the httpx library to efficiently process large datasets without blocking operations.

Bespoke: The crawler is custom-developed to meet the specific needs of the Connecting Threads project and specific museum collections. It is not a general-purpose web crawler but is tailored to interact with particular APIs and data structures.

Data Processing: JSON responses from museum APIs are parsed and validated using Pydantic models to ensure data integrity before database insertion. Image files are downloaded asynchronously and stored using Django's storage backend.

Rate Limiting: The crawler implements exponential backoff and respects API rate limits to maintain good citizenship with museum partners. Failed requests are logged and can be retried manually.

Open Source: The complete source code and documentation are available in our GitHub repository. The project is licensed under the MIT License, and contributions are welcome.

Data Quality & Review

All items retrieved by the crawler go through a review process before being published to the public database. When records are retrieved, they are stored in a catchment area of the Django application---a separate application designed to hold various items pending review. Once items have been reviewed or edited, they can be promoted to the main database for public access.
